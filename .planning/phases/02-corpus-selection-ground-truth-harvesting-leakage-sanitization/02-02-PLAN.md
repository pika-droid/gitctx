<context>
Retrieval evaluation requires rigorous, non-circular ground truth. If ground-truth labels are noisy or contain false associations (e.g. incidental issue mentions or bot churn), all downstream retrieval evaluation metrics will be contaminated.

Following user decisions D-05, D-06, D-07, D-08, and D-12:
1. `eval/harvest.py` mines local Git commit trailers and merges, querying GitHub's issue timeline API for authoritative closing events with offline disk caching in `eval/cache/` (D-05, D-06).
2. It extracts revert pairs (`git log --grep '^Revert "'`) capturing explicit semantic undo relationships (D-06).
3. Bot commits are filtered, labels are capped at max 3 commits per issue, and queries are tagged with `has_traceback` and `has_symbol_hint` metadata (D-06, D-12).
4. An interactive precision audit CLI samples 30 pairs, logs human evaluations to `eval/harvester_audit.md`, and computes sample precision with 95% Wilson Score confidence intervals, gating on $p \ge 0.85$ (D-07).
5. Harvested data is serialized to canonical JSONL schemas with cryptographic hashes in `eval/ground_truth/MANIFEST.toml` (D-08).
</context>

1. In `eval/harvest.py`, implement local git traversal and regex trailer mining:
   - Match action trailers in commit messages and PR merge bodies: `(?im)^[ \t]*(?:Fix(?:es|ed)?|Close[sd]?|Resolve[sd]?|Ref(?:erence[sd]?)?|Addresses|Related-to|Issues?):\s*(?:#|gh-)?(\d+)` and full GitHub issue/PR URLs `https?://github\.com/([A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+)/(?:issues|pull)/(\d+)`.
   - Match revert commits: subject matching `(?m)^Revert "(.+)"$` and commit body matching `(?m)^This reverts commit ([0-9a-f]{40})\.?$`.
2. Implement cached GitHub REST API client with rate-limit protection (D-05):
   - Check local disk cache in `eval/cache/<hash>.json` (keyed by SHA256 of endpoint URL).
   - If cache miss and online, make authenticated request using `GITHUB_TOKEN` or `GH_TOKEN` environment variable.
   - Query `/repos/{owner}/{repo}/issues/{issue_number}` (to fetch issue title and body) and `/repos/{owner}/{repo}/issues/{issue_number}/timeline` (to extract `closed` event `commit_id`).
   - If offline or unauthenticated, gracefully fall back to local trailer extraction.
   - Redact all tokens and credentials from logs, error messages, and cache files.
3. Implement bot author exclusion (D-06):

   - Limit to maximum 3 commits per issue.

   - `has_symbol_hint`: detect identifier names, method calls with parentheses (e.g. `foo()`, `Class.method`), or file paths with extensions (`.py`, `.rs`, `.go`, `.ts`).
   - Natural query text (including full issue body and tracebacks) is preserved un-redacted in the query field.
6. In `eval/tests/test_harvest.py`, write unit tests verifying:
   - Trailer regex extracts `Fixes #123`, `Closes gh-456`, `Resolves https://github.com/psf/requests/issues/789`.
   - Revert parser extracts target commit SHA from git revert commit text.
   - Bot commits are excluded from harvested labels.
   - Label capping limits labels to $\le 3$ items with correct confidence ordering.
   - `has_traceback` and `has_symbol_hint` flags correctly categorize synthetic issue texts.

<action>
Implement the interactive precision audit CLI, Wilson Score confidence interval calculation, and audit report logging in `eval/harvest.py` and `eval/harvester_audit.md` per D-07.

1. In `eval/harvest.py`, implement `compute_wilson_ci(k: int, n: int, confidence: float = 0.95) -> Tuple[float, float, float]`:
   - Compute point estimate $p = k / n$.
   - Compute standard normal quantile $z$ (for 95% confidence, $z = 1.959964$).
   - Apply the closed-form Wilson Score Interval formula:
     $$\text{center} = \frac{p + \frac{z^2}{2n}}{1 + \frac{z^2}{n}}$$
     $$\text{margin} = \frac{z \sqrt{\frac{p(1-p)}{n} + \frac{z^2}{4n^2}}}{1 + \frac{z^2}{n}}$$
     $$\text{lower} = \max(0.0, \text{center} - \text{margin}), \quad \text{upper} = \min(1.0, \text{center} + \text{margin})$$
2. In `eval/harvest.py`, implement interactive audit CLI (`python eval/harvest.py --audit <N>`):
   - Uniformly sample $N = 30$ query-commit pairs from harvested Set A records.
   - Render clean terminal inspection screen:
     - Sample index `[i/N]` and Repository name.
     - Issue Title and Body snippet.
     - Candidate Commit SHA, Subject, Author, and Diff stats.
     - Diff snippet showing touched files and modified lines.
     - Prompts user for judgment: `[v] Valid fix`, `[i] Invalid (unrelated)`, `[n] Noisy (partial/tangential)`.
     - Prompts for optional auditor notes.
   - Non-interactive mode (`--audit-batch <file.json>`): loads pre-recorded human judgments for reproducible CI testing.
3. Implement audit evaluation and report generation:
   - Compute sample precision: $p = N_{valid} / N_{total}$.
   - Compute 95% Wilson Score CI $[p_{lower}, p_{upper}]$.
   - Enforce pre-registered decision gate (D-07): Precision must satisfy $p \ge 0.85$ (e.g., $\ge 26/30$ valid pairs).
   - Write/append audit findings to `eval/harvester_audit.md` including:
     - Audit timestamp and auditor ID.
     - Summary statistics: Sample size $N$, Valid count, Invalid count, Noisy count, Precision $p$, and 95% Wilson CI.
     - Gating outcome: `PASS (p >= 0.85)` or `FAIL (p < 0.85)`.
     - Complete itemized audit table recording: QID, Repo, Commit SHA, Judgment, and Auditor Notes.
4. In `eval/tests/test_harvest.py`, add unit tests:
   - Verify `compute_wilson_ci` on known statistical reference values ($n=30, k=26 \implies p \approx 0.8667$, $CI \in [0.703, 0.947]$).
   - Verify boundary conditions ($k=0$, $k=n$).
   - Verify audit log parsing and decision gate assertion.
</action>
