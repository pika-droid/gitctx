<context>
Phase 2 establishes the empirical foundation for retrieval benchmarking. Without a representative, multi-language, commit-locked evaluation corpus, downstream retrieval metrics (Phase 3 ablation and Phase 10/11 benchmarks) are vulnerable to corpus drift, trivial synthetic artifacts, and language bias.

Following decisions D-01, D-02, D-03, and D-04:
1. We analyze a preset 15-repository candidate suite spanning Python (`requests`, `flask`, `fastapi`, `pydantic`, `httpx`), Rust (`ripgrep`, `fd`, `tokio`, `clap`, `actix-web`), and TS/Go (`express`, `trpc`, `gin`, `cobra`, `cli`).
2. We compute 11 metrics per candidate including first-parent commits, merge fractions, issue reference density, file churn storms, bot author fractions, and `.gitctxignore` exclusion rates.
3. We select a balanced triad spanning 3 size tiers (Small ~2k, Medium ~10-15k, Large ~30-50k+) across 3 languages (Python, Rust, TS/Go) meeting all hard criteria ($N_{traceable} \ge 150$, $f_{merge} < 0.40$, $f_{bot} \le 0.25$, non-universal squash).
4. We pin exact commit SHAs in `eval/corpus.lock.toml` under Invariant I6 and enforce strict checkout verification in `gitctx-eval`.
</context>

<action>
Implement the standalone multi-language repository profiler `eval/profile.py` and its test suite `eval/tests/test_profile.py` per D-01 and D-04.

1. In `eval/profile.py`, define the 15 preset candidate repositories (D-01):
   - Python: `psf/requests`, `pallets/flask`, `tiangolo/fastapi`, `pydantic/pydantic`, `encode/httpx`
   - Rust: `BurntSushi/ripgrep`, `sharkdp/fd`, `tokio-rs/tokio`, `clap-rs/clap`, `actix/actix-web`
   - TS/Go: `expressjs/express`, `trpc/trpc`, `gin-gonic/gin`, `spf13/cobra`, `cli/cli`
2. Implement built-in `.gitctxignore` matching rules and bot author filter per D-04:
   - Excluded file path patterns: `node_modules/**`, `vendor/**`, `*_pb2.py`, `*_pb2_grpc.py`, `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `Cargo.lock`, `poetry.lock`, `Pipfile.lock`, `go.sum`, `*.min.js`, `*.min.css`, `dist/**`, `build/**`, `.git/**`.
   - Bot author usernames: `dependabot[bot]`, `renovate[bot]`, `pre-commit-ci[bot]`, `github-actions[bot]`, `greenkeeper[bot]`, `snyk-bot`.
3. Implement `RepoProfiler` class computing the 11 structural metrics per candidate repo:
   - $N_{total}$: total commit count (`git rev-list --count HEAD`).
   - $N_{first\_parent}$: linear mainline commit count (`git rev-list --first-parent --count HEAD`).
   - $f_{merge}$: merge commit fraction ($N_{merge} / N_{total}$, where parent count $>1$).
   - $f_{issue\_ref}$: fraction of commits containing issue/PR references (`(?:#|gh-)\d+` or trailers `Fixes`, `Closes`, `Resolves`, `Ref`).
   - $N_{traceable}$: count of distinct closed issues extractable via commit message trailers or cached GitHub closing events.
   - $f_{squash}$: fraction of commit titles ending with `\(#\d+\)`.
   - Churn metrics: mean and median files modified per commit, count of reformat storms (commits touching $>25$ files).
   - Language composition: fraction of source files in target language (`.py`, `.rs`, `.ts`/`.js`, `.go`).
   - $f_{excluded}$: fraction of files/modifications matching `.gitctxignore` defaults.
   - $N_{revert}$: count of revert commits (`git log --grep '^Revert "'`).
   - $N_{renames}$: count of commits with file renames.
   - $f_{bot}$: fraction of commits authored by known bot usernames.
4. Support CLI arguments:
   - `--candidates`: path to candidate list or comma-separated list of repos.
   - `--repo-dir <path>`: base directory holding local git clones (`eval/corpus/` or temporary test fixtures).
   - `--output-md <path>`: destination path for `eval/corpus_selection.md`.
   - `--output-lock <path>`: destination path for `eval/corpus.lock.toml`.
   - `--offline`: profile strictly against local repositories without making network requests.
5. In `eval/tests/test_profile.py`, write pytest tests verifying:
   - Metric calculation logic on synthetic repositories (using fixtures created by `RepoBuilder` / `mkrepo.rs`).
   - `.gitctxignore` path matching correctly flags lockfiles and minified assets.
   - Bot author filtering correctly detects and isolates bot commits.
   - Profile summary structure matches required dataclass schema.
</action>

<threat_model>
## Trust Boundaries
- **TB-01 (External Repository Cloning)**: External git URLs cloned from GitHub into local `eval/corpus/`.
- **TB-02 (Lockfile Integrity)**: `eval/corpus.lock.toml` defining immutable ground truth for downstream benchmarks.

## STRIDE Threat Register

| Threat ID | Threat Type | Component | Description | Mitigation Strategy |
|-----------|-------------|-----------|-------------|---------------------|
| `T-02-01` | Tampering / Information Disclosure | Profiler Exclusions (`profile.py`) | Generated code or vendored packages (e.g. `node_modules`, lockfiles) artificially inflating churn or coupling statistics. | Enforce standard `.gitctxignore` defaults and bot author username filter per D-04; verify exclusions in unit tests. |
| `T-02-02` | Tampering / Repudiation | Corpus Pinning (`corpus.lock.toml`) | Repository drift (new commits on remote HEAD) invalidating evaluation ground truth and reproducibility (Invariant I6). | Enforce strict SHA pinning in `eval/corpus.lock.toml` and verify `assert_corpus_locked_sha` in evaluation harnesses per D-02, D-03. |
| `T-02-03` | Elevation of Privilege / Injection | Clone Automation (`clone_corpus.rs`) | Malicious repository URLs or path traversal in owner/repo names. | Validate GitHub HTTPS URLs with strict regex `^https://github\.com/[A-Za-z0-9_.-]+/[A-Za-z0-9_.-]+(?:\.git)?$` and sanitize directory names to `<owner>__<repo>`. |
</threat_model>
