<context>
Leakage of issue identifiers (`#123`, `Fixes #123`, `(#123)`) from commit messages and squash summaries into searchable index text produces artificial 100% recall that collapses in real developer usage where query issue IDs are unknown.

Furthermore, evaluating why-queries requires a non-circular, pre-registered benchmark dataset authored prior to inspecting tool search results.

Following user decisions D-09, D-10, D-11, D-12, D-13, D-14, D-15, and D-16:
1. We create shared test vectors in `tests/fixtures/sanitization_cases.json` covering $\ge 20$ edge cases.
2. We implement matching sanitizers in Python (`eval/sanitize.py`) and Rust (`crates/gitctx-core/src/sanitize.rs`), asserting 100% byte-for-byte output identity.
3. We strip squash PR suffixes, action trailers, attribution trailers, issue numbers, URLs, and merge boilerplate from indexed `chunk_text` while retaining `raw_message` in SQLite.
4. We curate 25–30 why-queries distributed across the 3 pinned repositories (8–10 per repo) across 4 categories (architectural decisions, bug root causes, API evolution, performance motivations) with a 60/40 dev/test split in `eval/ground_truth/set_b_why.jsonl`.
5. We lock all dataset files in `eval/ground_truth/MANIFEST.toml` via BLAKE3 and SHA256 digests before Phase 3 Python ablation begins.
</context>

   - Merge headers: `Merge pull request #123 from user/branch` and `Merge branch 'main' of ...` stripped.

   - Whitespace: consecutive blank lines collapsed to double newlines and trailing whitespace trimmed.
