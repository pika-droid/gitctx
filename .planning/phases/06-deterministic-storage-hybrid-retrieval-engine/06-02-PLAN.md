<context>
Phase 6 Plan 02 builds the full-text lexical search engine using Tantivy.
Key requirements:
1. Tokenization: Standard NLP stemmers damage code identifiers (e.g. `getter` -> `get`). The custom `CodeTokenizer` preserves full compound names while emitting lowercased subwords (e.g. `getUserById` -> `getUserById`, `get`, `user`, `by`, `id`) with zero destructive stemming (D-05).
2. Field Boosting: High boost on `qualified_name` (4.0) and `path` (2.0) ensures exact symbol and file matches surface at the top, while `commit_message` (1.2) and `chunk_text` (1.0) capture natural language intent (D-06).
3. Lifecycle: Cold indexing outputs to `.gitctx/tantivy.tmp/` and atomically swaps to `.gitctx/tantivy/` (D-07). Incremental updates append new documents directly via `IndexWriter` in <2 seconds (D-08).
</context>

<threat_model>
| Threat ID | STRIDE Category | Threat Description | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| T-06-04 | Tampering | Partial write during Tantivy index build corrupts search index segments. | Cold indexing writes to `.gitctx/tantivy.tmp/` and atomically renames the directory only upon successful commit (D-07). |
| T-06-05 | Information Disclosure | Sensitive credentials or high-entropy tokens indexed into Tantivy full-text index. | Chunks pass through `SecretRedactor` before being submitted to Tantivy document indexer (INDEX-03, PARSE-06). |
| T-06-06 | Denial of Service | Huge search query expressions causing expensive regex or Lucene expansion exhaustion. | Sanitize query inputs and limit maximum query term length and disjunction count in `QueryParser` (INDEX-03). |
| T-06-07 | Repudiation | Search hits return outdated or deleted `touch_id` references. | Touch IDs are immutable unsigned 64-bit integers tied strictly to SQLite primary keys (INDEX-01, INDEX-03). |
</threat_model>
