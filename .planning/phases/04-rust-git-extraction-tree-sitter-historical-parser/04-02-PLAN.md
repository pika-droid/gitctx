<context>
Phase 4 Plan 02 builds the historical AST extraction engine. Historical Git repositories contain thousands of code commits across multiple programming languages, and occasionally contain invalid syntax from work-in-progress or rebasing commits.

Following decisions D-01 through D-08, this plan implements:
1. Multi-language `LanguageBehavior` trait hierarchy for Python, Rust, JavaScript, TypeScript, Go, C/C++, Java, and PHP (mirroring `codanna`'s parser patterns).
2. `LanguageRegistry` mapping file extensions and shebang lines to language behaviors.
3. In-memory `BlobParseCache` (`lru::LruCache`) storing parsed symbols per blob OID to ensure 10k-commit indexing finishes within performance budgets.
4. Graceful degradation handler: when tree-sitter encounters syntax errors, cleanly extract intact functions as `ParseStatus::Ok` and emit a `<file_level>` touch with `ParseStatus::Degraded` for unresolved error regions.
5. Parse telemetry collecting `ok`, `degraded`, and `failed` statistics.
</context>

<threat_model>
| Threat | Mitigation |
| :--- | :--- |
| Deeply nested AST stack overflow | Use iterative tree cursor traversal or bounded recursion depth in AST walkers. |
| Multi-byte UTF-8 string slicing panic | Always use `code.get(start..end)` or UTF-8 boundary checks before indexing string slices. |
| Unbounded cache memory consumption | Bound `BlobParseCache` with fixed capacity (~50,000 entries) and LRU eviction policy. |
</threat_model>
