<context>
Phase 5 Plan 01 delivers the fundamental building blocks of function evolutionary tracking:
1. Universal symbol naming via standardized `QualName` conventions: using double-colon `::` notation for namespaces/classes/methods, angle-bracket scopes `::<nested_func>` for nested definitions, and `::<closure@Lline>` for anonymous closures across Python, Rust, JavaScript, TypeScript, Go, C/C++, Java, and PHP (D-12).
2. Lexical AST body normalization: stripping comments, docstrings, and whitespace, mapping string/number literals to `<str>`/`<num>`, and replacing non-keyword local variable identifiers with positional placeholders `var_0`, `var_1`, ... to make body fingerprints 100% invariant to local variable renames (M6) and formatting changes (M5) (D-01).
3. Deterministic 128-permutation MinHash fingerprinting: hardcoded 128-seed table with pure-Rust Murmur3-32, $k=3$ token shingles, length gating (< 10 tokens) for short functions, and bitwise Jaccard similarity estimation (D-02, D-03, D-04).
</context>

<threat_model>
| Threat | Mitigation |
| :--- | :--- |
| Non-deterministic hash permutations across platforms | Hardcode immutable 128 `u32` seed table and pure-Rust portable Murmur3-32 with no platform-dependent endianness issues (D-04, Invariant I2). |
| False positive matches on trivial getters/setters | Gate MinHash matching with token threshold check (`< 10` normalized tokens flagged as short function) (D-03). |
| Keyword collision during identifier replacement | Maintain explicit keyword set per language ensuring control structures (`if`, `for`, `return`, `match`) are never mapped to `var_N` (D-01). |
</threat_model>
