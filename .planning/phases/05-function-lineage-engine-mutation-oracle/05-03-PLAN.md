<context>
Phase 5 Plan 03 provides the rigorous empirical validation harness for the function lineage engine:
1. Synthetic mutation oracle evaluation: runs the `LineageResolver` over synthetic repositories generated by `MutationEngine` (Phase 1), validating links against `LineageGroundTruthManifest`. Measures per-class link-level Precision, Recall, and F1 across all 10 mutation classes (M1-M10), M8 decoy rejection rate ($\ge 0.95$), and end-to-end chain recovery at depths $D=2, 5, 10$ (D-13).
2. Threshold calibration tuning sweep: provides `gitctx-eval tune-thresholds` / `cargo xtask tune-lineage` running grid sweeps over $\tau_{\text{same}} \in [0.50, 0.85]$, $\tau_{\text{cross}} \in [0.65, 0.90]$, and $\tau_{\text{decoy}} \in [0.15, 0.35]$ on held-out calibration splits, emitting `eval/lineage_thresholds.json` (D-14).
3. `git log -L` heuristic oracle comparison: queries `git log -L :func:file` across historical repositories and classifies discrepancies into the 4 Discrepancy Taxonomy buckets: (1) Full Agreement, (2) gitctx Advantage (tracking moves/renames where `git log -L` halted), (3) git log -L Advantage, and (4) Ambiguous, quantifying the oracle's blindness (D-15).
4. Fast testing separation: unit/mutation tests execute in `< 5s` under `cargo test`, while corpus-wide oracle evaluation executes via `cargo xtask eval-lineage` (D-16).
</context>
