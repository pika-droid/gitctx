<context>
Phase 1 initializes the complete engineering foundation for gitctx. Following decisions D-01, D-02, D-03, D-04, and D-15, we set up a modular, layered Cargo workspace targeting Rust 2021 edition with MSRV 1.82+, `#![forbid(unsafe_code)]`, strict Clippy linting (`-D warnings`), pure Rust `xtask` command runner, and core data contracts.

`gitctx-core` serves as the leaf dependency holding domain models (`CommitId`, `FunctionTouch`, `LineageId`, `Citation`, `ParseStatus`), standard qualified naming conventions (`QualName`), `CoreError` via `thiserror`, and `ConfigHash` via BLAKE3 canonical JSON hashing.

Additionally, to ensure agents and developers can inspect, adapt, and reuse proven implementations (such as Sourcegraph's `codanna` code indexing engine, `tree-sitter` bindings, and `code-maat`), `xtask` provides a dedicated `clone-references` task targeting `reference_repos/`.
</context>

<threat_model>
## Trust Boundaries
- **TB-01 (Build and Dependency Ingestion)**: External packages from crates.io compiled into local binaries.
- **TB-02 (Configuration Serialization)**: Runtime configuration strings passed into `ConfigHash`.
- **TB-03 (Reference Repository Ingestion)**: External git URLs cloned into `reference_repos/`.

## STRIDE Threat Register

| Threat ID | Threat Type | Component | Description | Mitigation Strategy |
|-----------|-------------|-----------|-------------|---------------------|
| `T-01-SC` | Supply Chain / Tampering | Workspace Dependencies (`Cargo.toml`) | Malicious or compromised upstream crates pulled from crates.io during build. | Rely strictly on audited standard crates (`git2`, `tempfile`, `clap`, `thiserror`, `anyhow`, `blake3`, `serde`, `tracing`) vetted in Research Package Legitimacy Audit; pin exact versions in `Cargo.lock`. |
| `T-01-MEM` | Elevation of Privilege | Safe Workspace Crates | Memory unsafety or UB introduced through unconstrained `unsafe` blocks. | Enforce `#![forbid(unsafe_code)]` at crate roots per D-02. |
| `T-01-CFG` | Repudiation / Integrity | `ConfigHash` (`config.rs`) | Subtle differences in key ordering or whitespace causing mismatched config hashes across platforms. | Use sorted-key canonical JSON serialization before hashing with BLAKE3 per D-15. |
| `T-01-CLONE` | Tampering / Information Disclosure | Reference Cloning (`clone_references.rs`) | Arbitrary URL injection or uncontrolled repository execution during reference repository cloning. | Restrict default cloning targets to hardcoded, HTTPS-only official repository URLs; ensure `reference_repos/` is strictly ignored in `.gitignore` and excluded from workspace build artifacts. |
</threat_model>
