<context>
Ground-truth evaluation of function lineage tracking across renames, moves, and refactors (Phase 5) requires an unassailable oracle. Because `git log -L` is blind to cross-file moves and subtle AST transformations, we implement a synthetic mutation generator that deterministically transforms source code and produces structured ground-truth manifests.

Following user decisions D-09, D-10, D-11, D-12, D-13, D-14, and D-16:
1. `gitctx-eval` provides programmatic M1-M10 transformations (in-place rename, cross-file move, move+rename, signature change, reformatting, local var rename, function split, decoy delete+add, directory move, function copy).
2. Ground-truth lineages are written to `lineage_ground_truth.json`.
3. Invariant I1 (100% offline indexing and search) is enforced mechanically via unit test socket interception and Linux `unshare -n` runners.
4. Model downloading is established as an ahead-of-time setup phase via `cargo xtask download-models`.
5. `cargo xtask test-invariants` provides a unified test runner for all project invariants.
</context>

<action>
Implement the M1-M10 mutation classes, manifest serialization schema, and execution engine in `gitctx-eval` per D-09, D-10, D-11.

1. In `crates/gitctx-eval/src/mutator/transformations.rs`, define enum `MutationClass` (per D-09):
   - `M1_InPlaceRename`: Renames function `foo` -> `bar` within same file, body identical.
   - `M2_CrossFileMove`: Moves function `foo` from `a.py` to `b.py` without modifying signature or body.
   - `M3_MoveAndRename`: Moves function `foo` from `a.py` to `b.py` and renames to `bar`.
   - `M4_SignatureChange`: Adds, removes, or reorders function parameters (e.g. `foo(a, b)` -> `foo(a, b, timeout=10)`).
   - `M5_Reformatting`: Applies whitespace, indentation, docstring line-wrapping changes without changing AST semantics.
   - `M6_LocalVarRename`: Renames internal local variables inside function body while preserving name and signature.
   - `M7_FunctionSplit`: Extracts portion of function `foo` into new helper function `_foo_helper` (`derived_from` relationship).
   - `M8_DecoyDeleteAdd`: Deletes function `foo` and simultaneously adds unrelated function `foo_alt` in same commit.
   - `M9_DirectoryMove`: Relocates entire module/directory (e.g. `src/utils.py` -> `src/legacy/utils.py`).
   - `M10_FunctionCopy`: Copies function `foo` into `c.py` while retaining original in `a.py` (`COPIED` relationship).
2. In `crates/gitctx-eval/src/mutator/manifest.rs`, define JSON serializable data structures per D-10:
   - `SymbolLocation`: struct with `path: String`, `qualname: String`, `start_line: usize`, `end_line: usize`.
   - `GroundTruthRelation`: enum with variants `Exact`, `Renamed`, `Moved`, `SplitFrom`, `Decoy`, `Copied`.
   - `LineageLink`: struct with `commit_sha: String`, `mutation_class: MutationClass`, `source: SymbolLocation`, `target: SymbolLocation`, `relation: GroundTruthRelation`, `confidence_expected: f32`.
   - `LineageGroundTruthManifest`: struct with `schema_version: u32`, `created_at: String`, `chain_depth: usize`, `links: Vec<LineageLink>`, `metadata: HashMap<String, String>`.
   - Methods: `save_to_file(&self, path: &Path)`, `load_from_file(path: &Path) -> Result<Self, std::io::Error>`.
3. In `crates/gitctx-eval/src/mutator/engine.rs`, implement `MutationEngine`:
   - `apply_mutation(repo_builder: &mut RepoBuilder, class: MutationClass) -> Result<LineageLink, anyhow::Error>`: applies single mutation to base repo and creates commit.
   - `apply_chain(repo_builder: &mut RepoBuilder, classes: &[MutationClass]) -> Result<LineageGroundTruthManifest, anyhow::Error>`: applies sequential composite chain across commits (per D-11).
4. Export modules in `crates/gitctx-eval/src/mutator/mod.rs` and `crates/gitctx-eval/src/lib.rs`.
</action>

## Trust Boundaries
- **TB-01 (Network Ingress/Egress)**: Any external socket creation during indexing/test runs (strictly forbidden by Invariant I1).
- **TB-02 (Model File Storage)**: Local filesystem storage of downloaded embedding model weights.

## STRIDE Threat Register

| Threat ID | Threat Type | Component | Description | Mitigation Strategy |
|-----------|-------------|-----------|-------------|---------------------|
| `T-03-NET` | Information Disclosure / Tampering | Indexing & Retrieval Paths | Unintended network egress (e.g. telemetry, automatic model weight fetching) violating Invariant I1. | Enforce dual-tier verification: in-process socket interception + Linux `unshare -n` network namespace isolation in CI per D-13; runtime models strictly read from pre-downloaded local cache per D-14. |
| `T-03-MFST` | Tampering / Integrity | Manifest Generator (`manifest.rs`) | Malformed or inconsistent ground-truth manifests misleading downstream lineage evaluation benchmarks. | Strongly typed Rust structs with Serde schema validation and round-trip serialization tests. |
| `T-03-DOS` | Denial of Service | Composite Mutation Chains (`engine.rs`) | Excessive chain depth causing unbounded commit generation or filesystem exhaustion during tests. | Validate chain depth bounds (`1 <= chain_depth <= 20`) in CLI and test harnesses. |
</threat_model>
