# Plan 10-02: Automated performance benchmark harness

## Goal
Establish a performance benchmark harness to continuously validate that `gitctx` executes within its stated strict budgets for latency, memory, and database size.

## Implementation Details

### Benchmark Harness (`xtask bench`)
- Implemented a new `cargo xtask bench` command (`xtask/src/tasks/bench.rs`) that executes a suite of integration tests and times their duration against predefined SLAs.
- Validates 4 core operational budgets:
  1. **Dense Vector Search (20k vectors):** Asserts `p95 < 300ms` budget using SIMD cosine search and Rayon parallel scoring.
  2. **Tantivy BM25 Search:** Asserts `p95 < 300ms` budget using the custom Code Tokenizer and multi-field boosted search.
  3. **SQLite Write + Atomic Swap:** Asserts `< 2s incremental` write budget utilizing WAL mode, background writers, and the atomic directory swap protocol.
  4. **MCP JSON-RPC Round-Trip:** Asserts `< 500ms` budget for an AI agent to execute an `initialize -> tools/list -> tools/call` pipeline.

### Integration
- Registered the `bench` module in `xtask/src/tasks/mod.rs` and added the `Bench` subcommand to `xtask/src/main.rs`.

## Assumptions & Synthetic Generation
- **Functional E2E Benchmarking:** Instead of using a strict micro-benchmarking framework (like `criterion`), the harness acts as an E2E "dry-run" by invoking specific high-intensity integration tests via `cargo test`. 
- **Compilation Overhead:** The wall-clock elapsed time printed in the harness report includes cargo compilation overhead (since it invokes `cargo test` as a subprocess). While this inflates the printed duration, the underlying tests strictly measure and assert the execution times internally to guarantee the budgets are mathematically met.
