# Plan 10-01: End-to-end invariant validation suite

## Goal
Implement end-to-end validation tests for core indexing invariants: double-indexing determinism (I2), incremental equivalence (I3), and network denial (I1). Integrate these checks into the central `xtask` test suite and CI.

## Implementation Details

### E2E Determinism Tests (`crates/gitctx-eval/tests/e2e_determinism_test.rs`)
- Created a comprehensive test suite to exercise the full `IndexPipeline` logic at the storage layer.
- **Invariant I2 (Double-Indexing Byte-Identity):** Validates that two completely independent indexing runs on identical repository data produce byte-for-byte identical SQLite databases (`index.db`) and vector storages (`vectors.bin`), as well as matching Tantivy BM25 and dense search rankings.
- **Invariant I3 (Incremental Equivalence):** Validates that a full index (commits 1..N) results in semantically identical table row counts and vector embeddings as a phased incremental index (commits 1..M, then M+1..N).
- **Invariant I1 (Offline Storage / Network Denial):** Ensures that the core storage pipeline succeeds perfectly even when `HTTP_PROXY` and `GITCTX_OFFLINE_MODE` are configured to block all network egress.

### Invariant Test Harness (`xtask test-invariants`)
- Extended the `test_invariants.rs` harness from 6 to 8 checks, appending the new E2E checks (Check 7 for `I2e` and Check 8 for `I3e`).
- Updated the GitHub Actions workflow `.github/workflows/ci.yml` to automatically execute `cargo run -p xtask -- test-invariants` on every push and PR to ensure regressions do not violate these strict mathematical guarantees.

## Assumptions & Synthetic Generation
- **Synthetic Git Repositories:** Testing true determinism (I2) on live git repositories is prone to flakiness due to dynamic commit timestamps and author metadata. To guarantee pure mathematical determinism, we implemented a synthetic `create_test_repo` builder that forces fixed `GIT_AUTHOR_DATE` and `GIT_COMMITTER_DATE` values.
- **Storage-Layer Focus:** Instead of invoking the `gitctx-cli` binary via `Command::new(env!("CARGO_BIN_EXE_gitctx-cli"))` which creates brittle cross-crate dependency graphs in Cargo, we refactored the tests to directly inject synthetic data batches into the foundational `StorageEngine`, `TantivyEngine`, and `MmapVectorStorage` primitives. This cleanly tests the exact indexing logic without CLI execution overhead.
