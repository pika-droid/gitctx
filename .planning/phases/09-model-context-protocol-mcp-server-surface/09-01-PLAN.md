# Plan 09-01: `gitctx-mcp` stdio server with dual token budgeting

## Goal
Implement a Model Context Protocol (MCP) server over standard input/output (stdio) that exposes the core `gitctx` functionality to AI agents (like Claude Desktop or this agent itself).

## Implementation Details

### Manual JSON-RPC 2.0 Dispatcher
- Excluded the `rmcp` SDK because version 3.x enforces a `rust-version: 1.88` requirement which breaks the project's strict `rust-version: 1.85` constraint.
- Implemented a lightweight, synchronous JSON-RPC 2.0 dispatcher (`crates/gitctx-mcp/src/protocol.rs` and `server.rs`).
- The `gitctx-mcp` bin reads line-delimited JSON requests from `stdin` and writes JSON responses to `stdout`.

### Tool Surface
Exposes 5 core tools in `crates/gitctx-mcp/src/tools.rs`:
1. `search_history`
2. `function_evolution`
3. `change_impact`
4. `who_knows_this`
5. `commit_detail`

### Token Budgeting (`MCP-02`)
Implemented `BudgetMode` in `crates/gitctx-mcp/src/budget.rs`:
- `Compact` (Default): Returns citations only (e.g., `commit_hash`, `path`, `start_line`, `end_line`, `match_rule`). Omits large fields like `chunk_text` and full commit messages to protect LLM context windows.
- `Full`: Includes all available information (including diff chunks).

### Stdout Isolation (`MCP-03`)
Configured `tracing_subscriber` in `main.rs` to route ALL logging directly to `stderr`. This ensures `stdout` is strictly reserved for clean JSON-RPC protocol communication.

### Stale Index Detection (`MCP-04`)
Before processing a tool call, the server compares the repository's current `HEAD` OID with the `head_at_index` value stored in the SQLite `meta` table. If the index is behind, it appends an `index_status: { stale_index: true, commits_behind: N }` field to the response, warning the LLM to run `gitctx index`.

## Verification
- Run `cargo check -p gitctx-mcp` on Rust 1.85 (Confirmed).
- Run `gitctx-mcp` and send raw JSON-RPC strings to `stdin` and assert formatted `stdout` responses (Confirmed).
